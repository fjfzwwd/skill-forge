# 安全边界

Skill 本身就运行在有文件、shell、凭据权限的 Agent 里。结晶产物必须比原 SKILL.md **更受限**，不能更宽松。

## 默认拒绝

| 项 | 默认 | 解除条件 / 说明 |
|---|---|---|
| 执行外部 shell 命令 | 禁止 | **仅** `forge approve --enable-shell`（L2），写 `elevated_by` |
| 执行技能目录内 Python 脚本 | 禁止 | **仅** `forge approve --enable-run-script`（L3），写 `elevated_by` 且 `== approved_by` |
| 执行声明式 op 插件 | 禁止 | **仅** `forge approve --enable-plugins`（L3）；静态发现 + 哈希锁定 + 受限命名空间 |
| 机器产物自我提权 | 禁止 | `fill` 补丁设任一 `allow_* = true` 退出 2；`approve` 每次签发无条件重置三个开关再按显式参数授予 |
| 插件 import `os` / `subprocess` / `socket` / `open` | 禁止 | 运行时白名单 importer 抛 `ImportError`，受限 builtins 不含 `open` |
| 写文件 / 删除 / 移动 | 禁止 | 内置 op 白名单中不存在写操作；插件命名空间不提供 `open` |
| 网络访问 | 禁止 | 内置 op 无网络能力；`gates` 出现 `allow_network` 直接拒绝 |
| 读取 skill 目录之外的路径 | 禁止 | 编译期 `ir.bad_path` 拒绝绝对路径（含盘符/UNC）、`..`、URL、控制字符；运行期 `relative_to(ROOT)` 二次校验 |
| 读取环境变量 / 密钥 | 禁止 | 无对应 op；`run_script` 会继承环境，见下方 L3 说明；插件命名空间无 `os` |
| `eval` / `exec` / 任意表达式 | 禁止 | 条件用受限比较解析器，右值只允许字面量；插件源码在受限 namespace 里 `exec`，但插件自身拿不到 `eval` / `compile` / `open` |
| 无超时执行 | 禁止 | `shell` / `run_script` 默认 30s、最大 300s；`verify` 外层 60s |
| 机器草案自动编译 | 禁止 | `forge approve <dir> --yes --by <审阅者>` 显式签发；`fill` 不绕过 |
| 缺基线时静默通过 | 禁止 | `verify` 只在显式 `--update-baseline` 时创建基线；CI 缺基线判 FAIL |
| 源变更后自动重编译 | 禁止 | 漂移护栏拦截，`--force` 才允许并写审计 |
| 批量自动改动技能库 | 禁止 | `batch` 默认只读；`--propose` / `--compile-approved` 需显式开启 |

## 风险分级

| 级别 | 触发 | 能力 |
|---|---|---|
| L1 | 默认 | 12 个只读 op：计数、匹配、收集、读文本/JSON/CSV、哈希、存在性、正则提取、列提取、阈值决策 |
| L2 | `allow_shell=true` | 额外允许 `shell`（`shell=False` + `shlex.split` + 超时 + cwd 限定） |
| L3 | `allow_run_script=true` 或 `allow_plugins=true` | 额外允许 `run_script`（执行技能目录内任意 Python）或 `plugin_<name>`（受限命名空间内执行已声明插件） |

**唯一放通入口**：`forge approve --yes --by <姓名> --enable-shell` / `--enable-run-script` / `--enable-plugins`。签发时先把三个开关无条件重置为 `false`，再按显式参数授予，并写 `elevated_by` / `elevated_at`；`IR.validate` 要求 `elevated_by == approved_by`。IR 含特权步骤却未放通、或没有特权步骤却要求放通，均返回 2。补丁、草案、手工改 JSON 都不能绕过。

**L3 的诚实说明**：`run_script` 用当前解释器直接执行技能目录内的 `.py`，无 shell、有超时、stdout 截断 64 KiB、非 0 退出码报错、路径二次校验，但它**无法防住脚本自身联网、读环境变量或写文件**。插件机制更强一些：编译期只用 `ast.literal_eval` 读 `SPEC`（从不 import），运行时限制 builtins 与可 import 模块，禁掉 `open` / `os` / `subprocess` / `socket`，并用 `plugins_sha256` 锁定整个目录。但它**是受限命名空间，不是安全沙箱**——Python 对象内省仍可能逃逸。两者都只在源码可信、且你已逐行读过时开启。生成的精简 SKILL.md 与锁文件会标注风险等级。

## 实现约束

- 生成脚本只用 Python 标准库（`pathlib`, `json`, `re`, `hashlib`, `csv`, `io`, `subprocess`, `time`, `builtins`）。
- `doctor` 的 AST 可移植性门禁会在上架前拦下硬编码反斜杠路径、IO 调用缺 `encoding`、`shell=True`、`subprocess.run` 缺 `timeout`。
- `subprocess` 仅用于 `shell` 与 `run_script` op，一律 `shell=False`、参数数组传参、有超时、`cwd=ROOT`、UTF-8 解码。
- `decide.when` 用受限比较解析器，不用 `eval`，不接受属性访问、函数调用或任意表达式。
- 所有 `glob` 结果按 `root` 重新解析，拒绝逃逸出根目录的符号链接目标。
- 生成文件头带 `GENERATED BY skill-forge x.y.z - DO NOT EDIT`，避免人改了产物又被覆盖。
- 子进程输出统一 UTF-8 + `errors=replace`；runner 自身 `reconfigure` stdout/stderr，避免 Windows 非 UTF-8 代码页崩溃。

## 人审闸门

`propose` 会读原文、也会读被引用的 JSON 配置（用于推断 `json_get` 的键）。它只做只读推断，但**推断结果不等于授权**：

- 草案顶层 `review_status=PROPOSED`，每个 step 带 `proposal` 元数据（置信度 / 依据 / 命中原文）。
- `IR.validate` 双重拦截：顶层状态 + 每条残留元数据，任一存在即退出 2。
- `forge fill` 合并 Agent 补丁后仍为 `PROPOSED`，补丁步骤标 `confidence=agent`，原文留档。
- 唯一解锁方式是 `forge approve --yes --by <姓名>`，剥离元数据并写 `approved_by` / `approved_at`；它同时是 L2/L3 唯一放通入口。
- `fill` 的校验探针使用一次性签发人、临时镜像特权开关，只用于结构校验，不写入草案；补丁含特权步骤会在清单里提示签发所需 flag。
- `low` 置信度步骤、`proposal.unmapped` 与 L3 `suggestions` 会在 `review-sheet.md` 显式警告。
- `ci --strict` 把「有草案但无签发 IR」判为 FAIL，防止草案混进主干。

产物哈希锁只覆盖 4 个编译产物；人审清单、草案、基线、采样记录是运行期数据，不进锁，避免把分析产物误当成生成代码。

## 漂移、护栏与回滚

- `crystallize.lock.json` 记录 `source_sha256`、`ir_sha256`、4 个产物哈希、`approved_by`、三个特权开关与 `plugins_sha256`。
- `forge watch` 检出源、产物或 `plugins/` 任一文件变更 → DRIFT(1)，要求重新 propose → 人审 → compile。
- `compile` 的 `_drift_guard` 会拒绝在漂移源上重编译（即使 IR 写 `source_sha256: auto`）；`--force` 写 `build/override-audit.json`。
- `guard` 依据输出形状与 git 改动频率拒绝 `NOT_READY` 流程；`--force` 写 `build/guard-override.json`，**绑定源 sha256 且 24 小时 TTL**（含 `expires_at`），源一改或过期即失效；`watch` 会提示当前豁免状态。
- `report.measured.md`、`benchmark.json` / `.md`、`bench-cases.jsonl` 都是运行期数据，不进产物哈希锁；`measure` / `bench` 刷新它们不会触发 DRIFT。
- `forge rollback --yes` 从 `build/backup/SKILL.md` 恢复原文；该备份**只在首次编译创建**，重复编译不会覆盖。

## 人审清单（compile 前逐项确认）

1. 每个 code step 的 `source` 指回的原文，确实是该动作，不是文档示例。
2. `kept_for_model` 里没有漏掉需要判断的步骤。
3. `prohibitions` 原文禁止动作已完整搬到精简版。
4. `allow_shell` / `allow_run_script` / `allow_plugins` 保持 `false`；若确需放通，确认是自己用 `approve --enable-*` 显式授予，且 `elevated_by` 与 `approved_by` 一致、对应命令/脚本/`plugins/*.py` 已逐条读过；核对 `plugins_sha256`。
5. `verify --update-baseline` 已执行且 `verify --format jsonl` 通过；`watch` 为 CLEAN。
6. `guard` 不是 `NOT_READY`；若使用了 `--force`，已复核豁免原因。
